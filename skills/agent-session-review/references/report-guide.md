# Review Report Guide

Use the smallest format that makes evidence and uncertainty inspectable. In Chat, include:

1. **Scope and coverage:** current Session or verified project key; selected/distinct Sessions; native source boundary; evidence cutoff; excluded, inaccessible, ambiguous, or missing data. Avoid private IDs and raw content unless needed and authorized.
2. **Workflow reconstruction:** major observed phases and handoffs, including uncertainty about gaps. In project scope, preserve each Session's purpose and the cross-Session sequence.
3. **Assessment:** consider all seven dimensions from the framework; give evidence-backed findings, not a numeric maturity score. An `Insufficient Evidence` dimension is legitimate.
4. **Priority findings:** for each consequential loss or strength, show Evidence → Interpretation → Impact → Recommendation, with one of the three confidence labels. Differentiate necessary iteration from avoidable rework.
5. **Resource evidence:** show token/allowance counters only when native meaning and cutoff are reliable. Label missing counters `unavailable`; keep measured usage, estimates, quotas, and cost separate. A useful workflow review does not require a token table.
6. **Next changes and limits:** small actionable changes, behaviors worth keeping, unverified hypotheses, and known source gaps. Compare to a supplied prior report only when tasks and evidence are comparable. Present durable-policy candidates as proposals requiring approval.

Default to a complete Chat answer with no filesystem output. An authorized export may use this same structure; no cleaned-file inventory, analysis manifest, or fixed directory is required.
